# Jednorazowy formularz Dodo Pizza Polska

Минимальный статический проект: HTML, CSS и обычный JavaScript отправляют данные в Google Sheets через Google Apps Script. Сервер, Node.js, база данных и сборка не нужны.

> В `public/logo.svg` и `public/background.webp` находятся нейтральные локальные заглушки. Перед публикацией замените их утверждёнными бренд-материалами, сохранив имена файлов.

## Структура

```text
index.html
styles.css
script.js
config.js
vercel.json
.vercelignore
google-apps-script/
  Code.gs
public/
  background.webp
  logo.svg
```

## Локальный запуск

Самый простой вариант — открыть `index.html` двойным щелчком. Для проверки в условиях, близких к GitHub Pages, лучше запустить локальный статический сервер из корня проекта:

```bash
python3 -m http.server 8000
```

Затем открыть [http://localhost:8000](http://localhost:8000). До настройки Google Apps Script форма покажет сообщение об ошибке при отправке — это ожидаемо.

## Настройка Google Sheets и Apps Script

1. Создайте новую Google-таблицу.
2. Переименуйте лист в `Odpowiedzi`.
3. В первой строке по порядку добавьте колонки:

   ```text
   ID
   Data i godzina
   Imię
   Numer telefonu
   Adres e-mail
   Zgoda na przetwarzanie danych
   Zgoda marketingowa
   Źródło
   ```

4. Скопируйте ID таблицы из её URL. В адресе вида `https://docs.google.com/spreadsheets/d/ID_ТАБЛИЦЫ/edit` нужна часть между `/d/` и `/edit`.
5. В таблице выберите **Rozszerzenia → Apps Script**.
6. Удалите пример кода и вставьте содержимое `google-apps-script/Code.gs`.
7. В начале `Code.gs` замените `PASTE_SPREADSHEET_ID_HERE` на скопированный ID. Если лист называется иначе, измените также `SHEET_NAME`.
8. Сохраните проект.
9. Нажмите **Wdróż → Nowe wdrożenie**.
10. В типе развертывания выберите **Aplikacja internetowa**.
11. Для выполнения выберите владельца проекта (**wykonuj jako właściciel / me**).
12. Доступ предоставьте всем, у кого есть ссылка (**każdy / anyone**). В некоторых типах аккаунтов вариант может называться **Anyone with the link**.
13. Подтвердите запрошенные Google разрешения и завершите развертывание.
14. Скопируйте URL Web App, оканчивающийся на `/exec`.
15. Вставьте URL в `config.js`:

   ```js
   window.APP_CONFIG = {
     googleAppsScriptUrl: "https://script.google.com/macros/s/ВАШ_ID/exec"
   };
   ```

При изменении `Code.gs` создавайте новую версию развертывания через **Wdróż → Zarządzaj wdrożeniami → Edytuj → Nowa wersja**. Иначе опубликованный Web App продолжит исполнять старый код.

## CORS и формат запроса

Форма отправляет `URLSearchParams`, то есть обычный `application/x-www-form-urlencoded` POST без нестандартных заголовков. Это простой CORS-запрос без предварительного `OPTIONS`/preflight. Web App должен быть опубликован именно с доступом для всех по ссылке; закрытое развертывание вместо JSON вернёт страницу авторизации Google.

## Проверка отправки

1. Откройте форму через локальный сервер или опубликованный сайт.
2. Введите имя длиной не менее 2 символов.
3. Введите польский номер, например `123 456 789` или `+48 123 456 789`.
4. Введите корректный email и отметьте обязательное согласие.
5. Нажмите **Prześlij**.
6. Проверьте сообщение **Dziękujemy!** и новую строку на листе `Odpowiedzi`.

Телефон сохраняется в формате `+48XXXXXXXXX`, email — без пробелов и в нижнем регистре. Apps Script добавляет UUID и время в часовом поясе `Europe/Warsaw`. Согласия записываются как `TAK` или `NIE`. Заполненное скрытое honeypot-поле возвращает успех, но строку не создаёт.

Если отправка не работает, проверьте URL `/exec` в `config.js`, ID таблицы, точное имя листа и режим доступа Web App. Технические ошибки намеренно не показываются посетителю.

## Публикация через GitHub Pages

1. Создайте репозиторий на GitHub и загрузите файлы проекта в корень ветки.
2. В репозитории откройте **Settings → Pages**.
3. В **Build and deployment** выберите **Deploy from a branch**.
4. Выберите нужную ветку (обычно `main`) и папку `/ (root)`, затем нажмите **Save**.
5. Дождитесь публикации и откройте URL, который покажет GitHub.
6. Проверьте загрузку фона и логотипа, затем выполните тестовую отправку.

Все локальные ресурсы подключены относительными путями `./...`, поэтому сайт работает и в подпапке GitHub Pages. Тот же каталог можно без сборки публиковать на Cloudflare Pages или другом статическом хостинге.

## Публикация через Vercel

Проект уже подготовлен как обычный статический сайт. Сборка, `package.json`, Node.js и серверные функции Vercel не требуются. Форма продолжает отправлять данные напрямую в опубликованный Google Apps Script Web App из `config.js`.

1. Загрузите проект в репозиторий GitHub, GitLab или Bitbucket.
2. Войдите на [vercel.com](https://vercel.com) и нажмите **Add New → Project**.
3. Импортируйте репозиторий с проектом.
4. В настройках проекта проверьте:
   - **Framework Preset:** `Other`;
   - **Root Directory:** корень репозитория (`./`);
   - **Build Command:** оставить пустым;
   - **Output Directory:** оставить пустым (Vercel использует корень проекта).
5. Нажмите **Deploy**.
6. После публикации Vercel выдаст адрес вида `имя-проекта.vercel.app`.
7. Откройте форму по этому адресу и выполните тестовую отправку.

Файл `vercel.json` фиксирует режим статического проекта и не меняет работу формы. `.vercelignore` исключает из публичного развертывания README, исходник Google Apps Script и другие служебные файлы, но сохраняет их в репозитории. При каждом следующем push в production-ветку Vercel автоматически опубликует новую версию сайта.

Если после публикации форма открывается, но отправка не проходит, проверьте, что:

- в `config.js` находится актуальный URL Google Apps Script с окончанием `/exec`;
- Web App выполняется от имени владельца;
- доступ к Web App предоставлен всем;
- после изменения `Code.gs` была опубликована новая версия развертывания.

## Замена изображений

- Фон: замените `public/background.webp` своим WebP-файлом. Лучше использовать изображение шириной около 1920 px с разумным сжатием.
- Логотип: замените `public/logo.svg` официальным SVG. Если формат или имя меняются, обновите путь в `index.html`.

Не добавляйте секреты в `config.js`: URL публичного Web App по своей природе виден посетителям. Запись в таблицу защищается обязательной серверной валидацией и простым honeypot; для этого одноразового проекта CAPTCHA и отдельный backend не используются.
